# Задача 05. Ошибки конфигурации и mock-режим

## Промпт

Отдели демонстрационные данные от рабочего поведения. Удали фиктивный успех создания заявки при отсутствии Supabase. Удали подстановку реалистичных dashboard-данных при ошибке рабочей базы. Рабочая конфигурация должна fail closed и показывать понятное состояние ошибки; демонстрационный режим должен быть явным и не включаться из-за случайного исключения.

Найди пустые catch и широкие fallback по src. Исправь только те, которые маскируют потерю данных, неправильную авторизацию или недоступность базы. Не выводи пользователю секреты и внутренние сообщения Supabase. Добавь структурированное серверное журналирование там, где без него ошибка теряется.

## Готово, когда

- заявка не сообщает об успехе без фактического сохранения;
- сбой базы не выглядит как реальные пользовательские данные;
- demo/mock включается только явно;
- критические ошибки диагностируются без раскрытия секретов.

## Проверки

- целевые тесты измененной логики
- TypeScript
- ESLint измененных файлов
- ручной smoke-test конфигурации без Supabase
