# Задача 04. Календарь и цены

## Промпт

Установи одно однозначное правило хранения занятых дат и используй его во всех слоях. Исправь обнаруженный случай, когда диапазон занятости с одинаковыми startsOn и endsOn сохраняется, но не блокирует проживание в этот день. Согласуй клиентские помощники, серверную проверку, SQL-ограничения и формы.

Проверь расчет количества ночей, сезонных цен и агентской наценки на границах диапазонов. Не меняй продуктовую модель цен. Добавь регрессионные тесты для каждого исправленного случая. Если требуется миграция данных, сделай безопасную additive migration и задокументируй смысл границ дат.

## Готово, когда

- UI, сервер и база одинаково трактуют начало и конец диапазона;
- невозможно отправить заявку на занятые даты;
- цена по ночам и snapshot заявки совпадают;
- регрессионные тесты проходят.

## Проверки

- целевые тесты календаря и pricing
- TypeScript
- ESLint измененных файлов
- проверка миграции локально, если доступен Supabase CLI
