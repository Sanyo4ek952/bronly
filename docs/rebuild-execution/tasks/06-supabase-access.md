# Задача 06. Supabase, типы и права доступа

## Промпт

Усиль границу данных Bronly. Подключи сгенерированный тип Database к Supabase-клиентам и постепенно убери ручные приведения строк базы в критических сценариях. Сначала охвати auth/profile, properties, rooms, guest_requests, calendar, pricing и subscriptions.

Проверь, что server actions подтверждают роль и владение ресурсом, а RLS защищает тот же инвариант. Отдельно проверь самостоятельные номера, потому что старые policy могли предполагать обязательный property_id. Service role используй только в явно серверных операциях, где он необходим. Не переноси service role в клиентский bundle.

## Готово, когда

- критические запросы типизированы схемой базы;
- владелец меняет только свои данные;
- агент не изменяет данные владельца;
- самостоятельные номера покрыты RLS;
- публичная заявка валидируется сервером.

## Проверки

- TypeScript
- ESLint измененных файлов
- целевые тесты правил доступа
- локальные RLS smoke-tests, если доступна база
- production build как контрольный этап
