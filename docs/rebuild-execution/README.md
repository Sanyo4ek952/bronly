# План непрерывной переработки Bronly

Эта папка содержит исполняемую очередь задач для последовательной переработки существующего проекта без полного переписывания репозитория.

## Как запускать

1. Откройте MASTER_PROMPT.md.
2. Отправьте его Codex в задаче, открытой в корне репозитория.
3. Codex читает STATUS.md и выполняет ровно одну незавершенную задачу.
4. После успешной проверки Codex обновляет STATUS.md и создаёт новый чат для следующей задачи в этом же локальном проекте.
5. Новый чат получает короткий стартовый промпт из NEXT_TASK_PROMPT.md и читает только актуальное состояние и свой файл задачи.

Файлы в tasks являются отдельными готовыми промптами. Любой из них можно запускать вручную, если требуется выполнить только один этап.

## Почему один чат на задачу

История реализации не переносится между чатами. Общий контекст хранится в коде, продуктовых документах и STATUS.md. Это ограничивает размер контекста каждого чата и не заставляет следующего агента перечитывать обсуждение предыдущих этапов.

Все новые чаты запускаются последовательно в локальном checkout сохраненного проекта. Worktree для этой цепочки не используется, иначе незакоммиченные результаты предыдущей задачи могут оказаться недоступны следующей.

## Источники продукта

- docs/product/prd.md — основная спецификация.
- docs/product/decision-log.md — более новые продуктовые решения.
- docs/product/product-boundaries.md — границы продукта и изменения, требующие отдельного решения.
- docs/product/terminology.md — обязательная лексика интерфейса.
- AGENTS.md — правила работы в репозитории.

## Целевой результат

- основной сценарий владельца и гостя работает от начала до конца;
- календарь, цены, заявки, роли и подписка имеют проверяемую бизнес-логику;
- ошибки конфигурации не маскируются демонстрационными успехами или данными;
- интерфейс последовательно использует Tailwind CSS v4 и общие UI-компоненты;
- старые br-* стили удаляются по мере миграции экранов;
- агентский контур, коллекции, уведомления, рефералы и админка соответствуют PRD;
- проект проходит необходимые автоматические и ручные проверки.

## Порядок задач

1. Зафиксировать техническую базу.
2. Синхронизировать продуктовые документы.
3. Создать минимальную систему тестирования бизнес-логики.
4. Исправить календарь и расчеты цен.
5. Убрать ложные успешные ответы и скрытые ошибки.
6. Усилить типизацию Supabase и границы доступа.
7. Создать UI-основу на Tailwind.
8. Пересобрать основной сценарий владельца.
9. Пересобрать публичную страницу и заявку гостя.
10. Довести подписку.
11. Довести агентский контур.
12. Довести коллекции.
13. Довести уведомления и PWA.
14. Довести рефералы и админку.
15. Удалить остаточный технический долг и провести финальную проверку.

## Правило проверок

Каждая задача содержит свой набор проверок. Полную production-сборку не нужно запускать после каждого локального изменения. Она выполняется на контрольных этапах и в финальной задаче. Если проверка не относится к измененному коду, ее не запускают только ради количества.

## Когда цепочка останавливается

Цепочка завершается после задачи 15. Она может остановиться раньше только при продуктовом конфликте, необратимом действии, недоступном обязательном секрете или повторяющемся техническом блокере. Обычные предупреждения и исправимые ошибки не являются причиной оставаться в текущем чате.
