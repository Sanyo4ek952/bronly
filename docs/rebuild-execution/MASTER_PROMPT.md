# Главный промпт непрерывного выполнения

Запусти последовательную цепочку переработки Bronly. В этом чате выполни ровно одну задачу, затем создай отдельный новый чат для следующей задачи.

Перед началом:

1. Прочитай AGENTS.md и обязательные документы в указанном там порядке.
2. Прочитай docs/rebuild-execution/README.md и docs/rebuild-execution/STATUS.md.
3. Прочитай docs/rebuild-execution/NEXT_TASK_PROMPT.md.
4. Найди первую задачу со статусом in_progress или pending и открой только соответствующий файл из docs/rebuild-execution/tasks.
5. Проверь git status и сохрани все посторонние изменения пользователя.

Правила исполнения:

- Работай в текущем репозитории и не начинай проект заново.
- Выполни в этом чате только первую незавершенную задачу.
- Перед изменениями помечай текущую задачу in_progress в STATUS.md.
- Выполняй задачу полностью, включая критерии готовности и указанные в ней проверки.
- Используй Graphify для средних и крупных архитектурных задач согласно AGENTS.md. После принятых изменений обновляй граф для минимально необходимого scope.
- Исправляй найденные локальные дефекты, если исправление необходимо для критериев текущей задачи и не расширяет продуктовый scope.
- Не добавляй функции вне PRD и decision-log.
- Не маскируй ошибки mock-данными, фиктивным успехом или пустым catch.
- Не создавай дублирующиеся UI-компоненты. Сначала проверяй src/shared/ui, соседние widgets и docs/engineering/component-index.md.
- Для UI используй Tailwind CSS v4 и существующие токены. Удаляй старый CSS только после того, как его потребители мигрированы.
- Запускай только проверки, перечисленные в текущей задаче, плюс проверку, прямо необходимую для найденной ошибки.
- Если проверка упала, исправь причину и повтори только затронутые проверки.
- После успешной проверки запиши краткий результат и доказательства в STATUS.md и пометь задачу done.
- Не начинай следующую задачу в текущем чате.
- Найди следующую запись pending в STATUS.md.
- Если следующая задача есть, используй инструменты управления задачами Codex: сначала найди текущий сохраненный проект, затем создай новый чат в этом проекте с локальным environment. Не используй worktree, потому что цепочка последовательно продолжает изменения одного checkout.
- Пользователь явно разрешил автоматически создавать каждый следующий `pending`-чат этой цепочки без дополнительного подтверждения. Разрешение относится только к последовательной передаче между задачами 01–15 и не расширяет полномочия на публикацию, необратимые действия или изменение внешней production-среды.
- Назови новый чат по номеру и названию следующей задачи.
- Передай новому чату короткий текст из NEXT_TASK_PROMPT.md, подставив номер и имя файла следующей задачи. Не копируй историю, diff и полный отчет текущего чата.
- После создания нового чата один раз проверь, что он принят в работу. Не жди завершения следующей задачи и закончи текущий чат.
- Если создание нового чата временно недоступно, оставь в финальном ответе готовый короткий промпт и точное имя следующего файла. STATUS.md уже должен быть обновлен.
- Если контекст текущего чата был сжат до завершения задачи, снова прочитай STATUS.md и продолжи только текущую in_progress задачу.

Остановиться и запросить решение пользователя можно только если:

- обнаружен конфликт с PRD, decision-log, product boundaries или terminology;
- нужен секрет, внешний аккаунт или недоступная инфраструктура;
- требуется необратимое действие, публикация или изменение внешней production-среды;
- три последовательные попытки устранить один и тот же блокер не дали результата.

Если одна задача зависит только от недоступной внешней инфраструктуры, зафиксируй blocker в STATUS.md и создай новый чат для следующей независимой задачи. При продуктовом конфликте соблюдай conflict protocol из AGENTS.md и остановись без создания следующего чата.

Если незавершенных задач больше нет, не создавай новый чат. Проведи предусмотренную текущей задачей финальную проверку и сообщи итог всей цепочки.
