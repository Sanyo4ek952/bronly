# Roadmap Bronly

Bronly развивается как действующий продукт. Завершение первоначальной базовой версии не ограничивает дальнейшую разработку.

## Статусы инициатив

- `idea` — направление зафиксировано без обязательства реализации;
- `discovery` — исследуются ценность, риски и варианты решения;
- `approved` — продуктовое решение принято и записано в decision log или PRD;
- `planned` — определены объем, зависимости и критерии готовности;
- `in_progress` — идет реализация;
- `released` — функция выпущена и отражена в текущем baseline PRD.

## Правило продвижения

Инициатива, меняющая продуктовую модель или постоянные инварианты, не переходит в `planned`, пока решение не зафиксировано в `docs/product/decision-log.md`. После стабилизации решение переносится в `docs/product/prd.md`.

Обычные улучшения существующих сценариев могут планироваться напрямую по действующему PRD, если они не меняют роли, права, юридическую модель, подписку, заявку или границы публичного контура.

## Кандидаты для развития

| Инициатива | Статус | Следующий шаг |
|---|---|---|
| Расширенная аналитика | `idea` | Определить пользователей, метрики и состав отчетов |
| UTM-метки для публичных ссылок | `idea` | Определить модель атрибуции и хранение данных |
| Интеграции с площадками и channel manager | `idea` | Провести discovery по синхронизации и ответственности за конфликты |
| Онлайн-оплата проживания | `idea` | Отдельно проработать юридическую и платежную модель |
| Рейтинги и отзывы | `idea` | Определить участников, модерацию и связь с завершенной заявкой |
| Роли персонала владельца | `idea` | Спроектировать права и аудит действий |
| CRM-возможности | `idea` | Выделить минимальные сценарии без дублирования заявок |
| Мультиязычность | `idea` | Определить языки, контентную модель и правила fallback |
| SMS-уведомления | `idea` | Оценить провайдера, согласия и стоимость доставки |

Порядок и приоритет инициатив определяются отдельными продуктовыми решениями.
