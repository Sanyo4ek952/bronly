# D08 — Детали подборки владельца

Маршрут: `/dashboard/collections/[collectionId]`

Статус: дизайн зафиксирован до изменений production TSX в изолированном HTML-макете `D08.html`. Figma не использовалась: лимит Starter исчерпан, поэтому макет нельзя называть Figma-дизайном.

Опора: `docs/product/prd.md` §§4.1, 5.6, 5.7, 13.4, 15–17; `docs/product/decision-log.md` — «Коллекции»; `docs/design/rollout.md`; визуальный язык главной и проверенных D01–D07.

## Задача страницы

Дать владельцу одно рабочее место для готовой подборки: увидеть название и подпись гостя, скопировать или открыть публичную ссылку, проверить базовую статистику, добавить объект либо отдельный номер, удалить элемент, изменить названия и отправить подборку в архив. Страница не меняет модель данных: коллекция может содержать объекты и/или отдельные номера, а заявка по публичной ссылке всё равно создаётся только на конкретный `room_id`.

## Audit текущей реализации

### Данные и поведение, которые сохраняются

- server loader `getCollectionDetailData("owner", collectionId)` и `notFound()` для отсутствующей коллекции;
- `collection.title`, `guestLabel`, `slug`, `itemCount`, `viewsCount`, `lastOpenedAt`, `isArchived`;
- относительная публичная ссылка и копирование абсолютного URL текущего origin;
- состояния copy: idle, success на две секунды и ошибка с ручным fallback;
- формы `renameOwnerCollectionAction`, `archiveOwnerCollectionAction`, `addOwnerPropertyToCollectionAction`, `addOwnerRoomToCollectionAction`, `removeOwnerCollectionItemAction`;
- query feedback для success/error без изменения кодов server actions;
- обязательное внутреннее название `maxLength=120` и необязательное гостевое `maxLength=160`;
- два режима выбора: свои объекты и отдельные номера; уже добавленные варианты остаются видимыми и disabled;
- состав коллекции с различением «Объект целиком» / «Конкретный номер»;
- empty choices, пустой состав, archived read-only state и базовая статистика без расширенной аналитики;
- breadcrumbs, owner shell, auth/role guards, RLS, маршруты и redirect-поведение.

### Проблемы текущей композиции

- вся страница находится в большой `Panel`, внутри которой ещё четыре `Panel`, а элементы состава добавляют третий рамочный слой;
- page header использует технический заголовок «Коллекция владельца», а реальное название подборки спрятано во внутренней карточке;
- публичная ссылка, статистика, rename, archive и состав имеют одинаковый визуальный вес и конкурируют за внимание;
- две большие action-card для добавления вариантов создают лишнюю высоту и повторный padding;
- строки состава выглядят как отдельные карточки вместо одного читаемого списка;
- на mobile пользователь проходит несколько уровней рамок до первого рабочего действия;
- длинные title, guest label, item title/subtitle и неразрывные строки не имеют последовательного `overflow-wrap` guard.

## Reuse-аудит

- сохраняется общий `CollectionDetailSection`, потому что он уже является единственной owner/agent точкой detail-screen;
- owner получает opt-in layout `owner-detail`; default-разметка агента не меняется до D30;
- переиспользуются `DashboardPageNav`, `BottomSheet`, `Input`, `Button`, `ButtonLink`, `InlineNotice`, `StatusPill`, `AppIcon` и существующие collection formatters;
- общий `BottomSheet` уже покрывает dialog semantics, focus trap/restore, Escape, drag close, scroll lock и safe-area;
- новый shared primitive, новый токен и запись в `docs/engineering/component-index.md` не требуются;
- `Panel` остаётся только в неизменённом default-layout агента; owner-layout использует локальные semantic surfaces с одним владельцем padding.

## Композиция

### Desktop, 1440 px

- `DashboardPageNav` остаётся первой строкой;
- открытый header без карточки: eyebrow `ПОДБОРКА ДЛЯ ГОСТЯ`, реальное название коллекции как единственный `h1`, гостевая подпись и status pill;
- справа в header — primary `Скопировать ссылку` и secondary `Открыть`; feedback копирования находится рядом и объявляется через `aria-live`;
- под header — плоская шалфейная summary-полоса: варианты, открытия, последнее открытие и срок ссылки;
- основной layout — две колонки: широкая «Состав подборки» и узкая «Названия и доступ»;
- слева один surface: заголовок, два компактных add-action, затем плоский список элементов с разделителями;
- справа один settings surface: два последовательных поля, submit, пояснение о базовой статистике и отдельная danger-зона архивирования, отделённая линией;
- публичный путь остаётся видимым в header как переносимый текст, но не создаёт отдельную вложенную карточку;
- back-navigation не дублируется дополнительной кнопкой «К списку коллекций».

### Mobile, 390 и 320 px

- header, copy/open actions и summary складываются в одну колонку;
- actions становятся полноширинными touch targets не меньше 44 px;
- summary становится сеткой 2×2 с внутренними разделителями и одним внешним padding;
- main layout становится одноколоночным: сначала состав и добавление вариантов, затем настройки и архив;
- два add-action складываются вертикально на 320 px и не содержат вложенных поверхностей;
- строки состава используют одну колонку identity, метку типа и отдельную кнопку удаления; все тексты получают `min-width: 0` и `overflow-wrap:anywhere`;
- bottom navigation и safe-area owner shell сохраняются;
- horizontal overflow не маскируется `overflow-hidden` на странице.

## Modal / sheet выбора

- открывается существующий `BottomSheet` с реальным `role="dialog"`, заголовком и описанием;
- режим «Объекты» показывает только доступные owner-объекты, режим «Отдельные номера» — доступные owner-номера;
- строка выбора показывает title, subtitle, scope и состояние «Уже в подборке»;
- выбранный вариант остаётся видимым, но submit disabled;
- empty choices показывают отдельное объяснение для объектов или номеров;
- на desktop sheet ограничена читаемой шириной, на mobile занимает ширину viewport и учитывает safe-area;
- resize при открытом sheet не должен снимать focus trap или body scroll lock; Escape и close-button возвращают фокус инициатору.

## Состояния

| Состояние | Представление |
| --- | --- |
| active | все add/edit/remove/archive действия доступны |
| archived | status `Архив`; add/edit/remove/archive disabled; явное warning «только просмотр»; публичная ссылка не обещается доступной гостю |
| пустой состав | спокойный empty block внутри единственной surface и обе add-action доступны |
| нет открытий | `0` и `Пока не открывали` в summary |
| нет guest label | под `h1` показывается нейтральная фраза «Для гостя используется это же название» |
| query success | существующий `InlineNotice` между header и summary |
| query/server error | существующий error feedback без изменения mapping или server action |
| native validation | обязательное поле title блокирует submit и получает фокус |
| loading | route-level server loading остаётся за существующей Next boundary; макет показывает skeleton без новой client state machine |
| copy success/error | текст кнопки и `aria-live` feedback; при ошибке ссылка остаётся доступной для ручного выделения |
| empty choices | пояснение внутри sheet без disabled пустого submit |
| длинные строки | перенос title/guest label/public path/item names/subtitles без выхода за viewport |

## Доступность и интеракции

- один `h1` — реальное название подборки; состав и настройки имеют связанные `h2`;
- status не кодируется одним цветом: виден текст `Активна` / `Архив`;
- статистика оформлена `dl/dt/dd`;
- публичная ссылка доступна для ручного копирования, copy feedback объявляется через `aria-live="polite"`;
- add-action — настоящие `button`, remove/archive/rename остаются настоящими server forms;
- modal сохраняет dialog label/description, focus trap, Escape, focus restore и scroll lock shared `BottomSheet`;
- keyboard order: back/breadcrumbs → copy/open → add object/add room → remove actions → rename fields/save → archive → shell navigation;
- глобальное `a { color: inherit }` не должно лишить primary link белого текста — проверяется computed contrast;
- disabled archived actions не попадают в keyboard trail.

## Ограничение изменений

D08 меняет только owner-вариант `/dashboard/collections/[collectionId]` через opt-in layout. `/agent/dashboard/collections/[collectionId]`, D06, D07, server actions, validation, data loaders, auth, RLS, публичные страницы, коллекционные данные и маршруты не меняются. Не добавляются восстановление архива, расширенная аналитика, каталог или новые бизнес-функции.

Production-данные не переименовываются, не архивируются, не пополняются и не очищаются ради QA. Copy и открытие существующей публичной ссылки допустимы как read-only. Server submit/mutations остаются непроверенными без явно разрешённой staging fixture.

## Демонстрационные данные макета
