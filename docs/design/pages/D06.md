# D06 — Подборки владельца

Маршрут: `/dashboard/collections`

Статус: реализовано и проверено на авторизованной локальной странице; Figma не использовалась из-за исчерпанного лимита Starter, поэтому отдельный дизайн до production TSX зафиксирован в изолированном HTML-макете `D06.html`.

Опора: `docs/product/prd.md` §§4.1, 5.6, 5.7, 13.4, 15–18; `docs/product/decision-log.md` — «Коллекции»; `docs/design/rollout.md`; визуальный язык главной и проверенных D01–D05.

## Задача страницы

Дать владельцу компактный обзор созданных подборок: быстро отличить активные подборки от архива, увидеть состав и базовую статистику открытия, перейти к деталям или начать создание новой подборки. Страница остаётся списком: создание и редактирование живут на отдельных маршрутах D07/D08.

## Audit текущей реализации

### Данные и функции, которые сохраняются

- server loader `getCollectionListData("owner")` и существующий порядок внутри набора данных;
- название подборки и необязательная подпись гостя;
- активное/архивное состояние;
- количество элементов, количество открытий и время последнего открытия;
- переход в `/dashboard/collections/[collectionId]` всей строкой;
- переход в `/dashboard/collections/new`;
- общий empty state;
- desktop sidebar, mobile bottom navigation, auth/role guards и RLS;
- бессрочная жизнь подборки до архивации и только базовая статистика без расширенной аналитики.

На странице не появляются архивирование, восстановление, копирование ссылки или редактирование: эти действия принадлежат экрану деталей и не проверяются в D06.

### Проблемы текущей композиции

- page header, пояснение, CTA и список находятся внутри одной большой `Panel` с внешним `padding: 24px`;
- пояснение о статистике оформлено второй рамочной поверхностью внутри панели;
- desktop дублирует CTA в header и карточке создания, хотя одновременно нужен один понятный вход;
- каждая подборка — высокая карточка с `min-height: 176px`, поэтому три коротких записи занимают непропорционально много места;
- active и archived записи смешаны в одной сетке, хотя состояние влияет на дальнейшую работу владельца;
- загруженное `lastOpenedAt` не показывается, из-за чего базовая статистика неполна;
- на mobile одинаковые панели, notice и CTA создают длинную последовательность `padding внутри padding` до первого рабочего элемента.

## Reuse-аудит

- сохраняется текущий `CollectionListSection`, потому что он уже является общей owner/agent точкой списка;
- owner получает opt-in layout, а default-разметка агента не меняется до D29;
- переиспользуются `ButtonLink`, `StatusPill`, `AppIcon` и `buildCollectionSubtitle`;
- `Panel` остаётся только в неизменённом default-layout агента; owner-layout использует локальные semantic sections и разделители;
- новые shared primitives, токены и записи в `docs/engineering/component-index.md` не требуются.

## Композиция

### Desktop, 1440 px

- открытый header без карточки: eyebrow `ПОДБОРКИ ДЛЯ ГОСТЕЙ`, заголовок `Коллекции`, короткое описание и один CTA `Создать подборку` справа;
- плоская шалфейная summary-полоса из четырёх значений: всего, активные, архив, открытия;
- под summary — короткое текстовое пояснение, что статистика базовая; отдельная notice-card не нужна;
- секция `Активные подборки` содержит одну кремовую поверхность со строками и разделителями;
- каждая строка показывает название, гостя, статус, количество вариантов, открытия и последнее открытие; вся строка ведёт в существующий detail-route;
- архив вынесен в отдельную секцию ниже с той же структурой и более спокойным статусом;
- нет карточки создания внутри списка, повторного CTA и панелей внутри панелей.

### Mobile, 390 и 320 px

- header и CTA складываются в одну колонку; CTA занимает ширину контента;
- summary перестраивается в сетку 2×2 с одним владельцем padding и внутренними разделителями;
- строка списка становится компактной карточной строкой внутри общей секции: identity и статус сверху, три показателя ниже;
- длинные названия и подписи гостя переносятся, даты не выходят за viewport;
- touch targets строк и CTA не меньше 44 px;
- bottom navigation shell остаётся видимой, контент получает её существующий safe-area отступ;
- горизонтального scroll и маскирующего `overflow-hidden` у страницы нет.

## Состояния

| Состояние | Представление |
| --- | --- |
| активные и архивные записи | две отдельные секции с собственными счётчиками |
| только активные | только секция активных; пустой архив не рисуется |
| только архив | только секция архива; summary сохраняет все показатели |
| нет открытий | `0` в summary и `Пока не открывали` в строке |
| нет подписи гостя | строка `Для гостя` не рисуется |
| длинное название/подпись | перенос внутри identity-column без выхода за viewport |
| пустой список | один спокойный empty block с иконкой, объяснением и CTA |
| loading/error loader | существующая server-граница; D06 не меняет data loader или error handling |

## Доступность и интеракции

- `h1` один; секции имеют связанные `h2` и счётчики не заменяют текстовые названия;
- status не кодируется одним цветом: видны тексты `Активна` / `Архив`;
- вся строка — один link с полным доступным именем; внутри нет вложенных интерактивных элементов;
- hover не является единственным сигналом: доступен общий `focus-visible` ring;
- статистика оформлена через `dl/dt/dd`;
- глобальное `a { color: inherit }` не должно лишать primary CTA белого текста — проверяется computed style;
- keyboard QA проверяет CTA, строки подборок, sidebar и mobile navigation;
- на D06 нет filters, menus, copy и modal; resize открытой modal неприменим.

## Ограничение изменений

D06 меняет только owner-вариант списка `/dashboard/collections`. Маршруты `/dashboard/collections/new` и `/dashboard/collections/[collectionId]`, agent collections, data loader, server actions, RLS и публичные страницы не меняются. Production-данные не создаются, не архивируются и не публикуются.

## Демонстрационные данные макета

В `D06.html` используются три изолированные записи: две активные и одна архивная подборка, включая длинную подпись гостя и состояние без открытий. Эти данные не переносятся в production.

## План проверки

1. Поднять `D06.html` по HTTP и снять 1440×900, 390×844 и 320×720 до внедрения.
2. Проверить `clientWidth === scrollWidth`, переносы длинного текста, видимость CTA/строк и focus-visible.
3. После внедрения проверить точный dev-сервер worktree на 1440/390/320 и промежуточных 821/900/1024/1180/1280.
4. Проверить DOM `scrollWidth/clientWidth`, sidebar/bottom-nav breakpoints, computed contrast primary CTA и строк, отсутствие console/Next overlays.
5. Клавиатурой пройти CTA и detail-links; переход в D08 проверить read-only и вернуться назад. Мутации не выполнять.

Проверка выполнена 2026-09-16 через локальный HTTP-сервер `http://localhost:8016/D06.html` в Chromium. Проверялся изолированный HTML-макет до изменений production TSX.

## Live QA production-компонентов

Проверка выполнена 2026-09-16 на авторизованном маршруте `http://localhost:3016/dashboard/collections` в отдельном webpack dev-сервере этого worktree. Использован локальный env-механизм без вывода значений секретов, чтения cookies/tokens и обхода auth. Production-данные не создавались, не архивировались и не публиковались.

- `1440 × 900`: sidebar виден, mobile navigation скрыта; header, summary, active и archive полностью помещаются по ширине; `clientWidth = scrollWidth = 1440`.
- `390 × 844`: sidebar скрыт, mobile navigation видна; CTA имеет размер `351 × 46`, summary 2×2, строки имеют ширину `349px`; `clientWidth = scrollWidth = 375` с учётом scrollbar.
- `320 × 720`: CTA, section headings и все три строки находятся внутри viewport; у строк `clientWidth = scrollWidth = 279`; `documentElement.clientWidth = scrollWidth = 305`.
- Промежуточные `821 / 900 / 1024 / 1180 / 1280`: на каждой ширине `documentElement.clientWidth === scrollWidth`, `body.scrollWidth` совпадает, строки имеют нулевую разницу `scrollWidth - clientWidth`, CTA не пересекает правую границу. На 821–1024 работает mobile shell, на 1180–1280 — desktop sidebar.
- Отдельно проверены все видимые DOM-элементы на выход за левую/правую границу: offenders нет; `html` и `body` имеют `overflow-x: visible`, то есть результат не замаскирован `overflow-hidden`.
- Финальная структура заголовков: один `h1` `Коллекции`, затем два `h2` `Активные подборки` и `Архив`; Next/error overlay отсутствует.
- Read-only переход по реальной строке открыл `/dashboard/collections/[collectionId]`, после `Back` восстановлен точный D06 route. Создание, сохранение, архивирование, удаление и copy не запускались.
- На D06 нет page-level filters, menu, copy или modal. Дополнительно проверено shell-меню `Ещё`: `Shift+Tab` с close-кнопки остаётся внутри sheet; resize открытого sheet с 320 до 1180 и последующий `Escape` закрывают dialog, снимают `body overflow: hidden` и не оставляют focus trap.
- Desktop и mobile keyboard trail прошёл CTA, три detail-links и навигацию. CTA получает focus ring `4px`, строки — внутренний ring `3px`.
- Computed contrast с учётом глобального `a { color: inherit }`: primary CTA `5.17:1`, summary labels `4.51:1`, пояснение статистики `4.63:1`, заголовок строки `15.57:1`.
- Browser console errors: `0`. В server dev-log присутствовал только существующий Next.js warning о глобальном `scroll-behavior: smooth`, уже отмеченный в D05 и не связанный с D06.

### Дополнительный аудит узкого desktop и длинного текста

После review отдельно проверены `761 / 780 / 1025 / 1100 / 1120 / 1150 px` и точная граница shell `1079 / 1080 / 1081 px`. Для проверки использовался временный локальный route с тем же production-компонентом и изолированными данными: длинное обычное название, длинный `guestLabel`, одно неразрывное слово в названии и `guestLabel`, четырёхзначный item count и шестизначный views count. Route после QA удалён; записи в БД и server actions не выполнялись.

Первый прогон обнаружил скрытый `overflow-clip` edge case только на искусственном неразрывном слове: при `761 px` строка имела `clientWidth 712 / scrollWidth 813`, при `780 px` — `731 / 813`, при `1100 px` — `796 / 813`. Last-opened и Chevron оставались видимы, но текстовый overflow маскировался внешним `overflow: clip`. Для title и `guestLabel` добавлен локальный `overflow-wrap: anywhere`; общий row layout, shell breakpoint и default agent layout не менялись.
