# D30 — Детали подборки агента

Маршрут: `/agent/dashboard/collections/[collectionId]`

Статус: route-specific контракт; shared implementation уже внедрён.

## Продуктовая опора

- `docs/product/prd.md`, §§5.5–5.6 и 8.1 — агент управляет персональной подборкой и добавляет только свои варианты либо варианты по активному сотрудничеству.
- Расширенная аналитика, автоматические рекомендации и общий каталог требуют отдельного продуктового решения.

## Переиспользование

Маршрут использует `CollectionDetailSection` и тот же opt-in `owner-detail` presentation, который был проверен в D08. Agent-specific loaders, actions, breadcrumbs и пояснения сохраняются. Отдельная копия detail UI не создаётся.

## Композиция и состояния

- breadcrumb и открытый identity header подборки;
- публичная ссылка, статус и два показателя в одной обзорной зоне;
- плоский список вариантов с действиями добавления и удаления;
- rename/archive отделены от основного списка, но не вложены в дополнительные карточки;
- active, archived, empty choices, success/error feedback и bottom sheet сохраняются.

## QA

Representative active state проверен на `1440 × 900`, `390 × 844` и `320 × 720`. Длинные названия и URL переносятся, action rows переходят в один столбец. Статический route audit подтверждает сохранение agent actions, `notFound`, query feedback и ограничения вариантов.
