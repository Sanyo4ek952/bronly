# D07 — Новая подборка владельца

Маршрут: `/dashboard/collections/new`

Статус: реализовано и проверено на production-компоненте в изолированном локальном fixture; Figma не использовалась из-за исчерпанного лимита Starter, поэтому дизайн до production TSX зафиксирован в `D07.html`.

Опора: `docs/product/prd.md` §§4.1, 5.6, 5.7, 13.4, 15–17; `docs/product/decision-log.md` — «Коллекции»; визуальный язык главной и проверенных D01–D06.

## Задача страницы

Дать владельцу короткий и понятный первый шаг создания подборки: назвать её для собственного кабинета и, при необходимости, задать отдельное название для гостя. После успешного создания существующий server action переводит пользователя на страницу деталей, где он добавляет объекты и/или отдельные номера. Выбор состава и управление публичной ссылкой относятся к D08 и не переносятся в D07.

## Audit текущей реализации

### Данные и поведение, которые сохраняются

- server action `createOwnerCollectionAction` и mutation `createCollection({ role: "owner" })`;
- обязательное поле `title` с `maxLength=120`;
- необязательное поле `guestLabel` с `maxLength=160`;
- существующие query feedback-коды, redirect на `/dashboard/collections/[collectionId]` и revalidation;
- native required-validation браузера и server validation;
- back-navigation, breadcrumbs, owner shell, auth/role guards и RLS;
- коллекция создаётся пустой; объекты и номера добавляются только на следующем экране.

### Проблемы текущей композиции

- вся страница заключена в большую `Panel`, внутри которой форма заключена во вторую `Panel`;
- два слоя padding и рамок отделяют короткую форму от page shell и визуально делают её сложнее;
- заголовки «Создать коллекцию владельца» и «Новая коллекция» дублируют друг друга;
- кнопка «К списку коллекций» повторяет уже видимую back-navigation;
- два поля стоят в две колонки, хотя второе логически уточняет первое и последовательное чтение лучше;
- текст обещает «сразу перейти к управлению», но не объясняет простой двухшаговый сценарий без добавления новой логики.

## Reuse-аудит

- сохраняется общий `CollectionCreateSection`, потому что его использует и agent-route;
- owner получает opt-in layout; default agent-layout остаётся без визуальных и поведенческих изменений;
- переиспользуются `DashboardPageNav`, `Input`, `Button`, `ButtonLink`, `InlineNotice` и текущие токены;
- новый reusable component, shared variant или global token не создаётся;
- `docs/engineering/component-index.md` не меняется.

## Композиция

### Desktop, 1440 px

- компактная back-navigation остаётся первой строкой;
- открытый header без карточки: eyebrow `НОВАЯ ПОДБОРКА`, один `h1` `Соберите варианты для гостя` и короткое описание;
- под header — единая белая form-surface без вложенных рамочных панелей;
- слева — заголовок шага и два поля, поставленные последовательно;
- справа — спокойная шалфейная contextual-зона «Что дальше» внутри того же form-surface, а не отдельная вложенная карточка;
- footer формы отделён тонкой линией: вторичная ссылка назад и primary submit;
- ширина полей ограничена читаемой колонкой, свободное пространство не растягивает input до всей страницы.

### Mobile, 390 и 320 px

- header, поля, contextual-зона и действия складываются в одну колонку;
- form-surface имеет один уровень padding: `18px` на 390 и `14px` на 320;
- обе кнопки полноширинные, primary идёт первой визуально и остаётся удобной для большого пальца;
- длинные title, labels, description и неразрывные слова переносятся без горизонтального scroll;
- bottom navigation и safe-area owner shell сохраняются.

## Тексты формы

- eyebrow: `НОВАЯ ПОДБОРКА`;
- `h1`: `Соберите варианты для гостя`;
- intro: `Сначала назовите подборку. Объекты и номера вы добавите на следующем шаге.`;
- секция: `Название подборки`;
- обязательное поле: `Название в кабинете`;
- необязательное поле: `Название для гостя`;
- contextual-зона: `Что дальше` / `После создания откроется страница подборки. Там можно добавить объекты и отдельные номера, затем отправить гостю готовую ссылку.`;
- primary action: `Создать подборку`;
- secondary action: `Вернуться к списку`.

Тексты не обещают публикацию, автоматическое подтверждение заявки или добавление вариантов на этом шаге.

## Состояния

| Состояние | Представление |
| --- | --- |
| default | два пустых поля, primary submit и ссылка назад |
| заполнено только обязательное поле | форма доступна к отправке, гостю будет показано внутреннее название по существующей логике |
| native validation | browser message у обязательного `title`, фокус остаётся на поле |
| server/query error | существующий `InlineNotice` перед form-surface, без изменения кодов и server action |
| success | существующий redirect на D08; transient success на этой странице не добавляется |
| loading | нативное состояние server form; новая client-state машина не вводится |
| empty data | неприменимо: D07 не загружает объекты или номера |
| длинные значения | inputs остаются внутри поверхности, labels/descriptions переносятся |

## Доступность и интеракции

- на странице один `h1`, затем `h2` для формы и `h3` для contextual-зоны;
- labels связаны с inputs, description гостевого названия остаётся в `aria-describedby` через shared `Input`;
- обязательность задаётся реальным `required`, а не только визуальной меткой;
- keyboard order: back link → breadcrumbs → title → guest label → return link → submit → shell navigation;
- focus-visible берётся из существующих shared primitives;
- глобальное `a { color: inherit }` не должно менять белый текст primary CTA; проверяется computed contrast;
- D07 не содержит выбора объектов/номеров, modal или focus trap. Эти взаимодействия относятся к D08; их поведение не меняется этой задачей.

## Responsive и overflow guard

- точная граница owner shell проверяется на `1079 / 1080 / 1081 px`;
- дополнительно проверяются `761 / 780 / 821 / 900 / 1024 / 1100 / 1180 / 1280 px`;
- проверяются `documentElement` и form-surface `scrollWidth/clientWidth`;
- отдельная isolated fixture использует title/label/description с длинными словами и неразрывной строкой;
- overflow нельзя маскировать `overflow-hidden` на странице.

## Ограничение изменений

D07 меняет только owner-вариант `/dashboard/collections/new`. Agent-route `/agent/dashboard/collections/new`, список D06, details D08, server actions, validation, data model, auth, RLS, публичные страницы и маршруты не меняются. Production-данные не создаются; submit не выполняется без явно разрешённой staging fixture.

## Результаты визуального QA макета

Проверка выполнена 2026-09-16 через локальный HTTP-сервер `http://127.0.0.1:8017/D07.html` в Chromium. Проверялся изолированный HTML-макет до изменений production TSX.

- `1440 × 900`: desktop sidebar виден, bottom navigation скрыта; открытый header и единая form-surface остаются в пределах читаемой ширины `1000px`;
- `390 × 844`: mobile navigation видна; форма складывается в одну колонку, primary action идёт раньше secondary и обе кнопки полноширинные;
- `320 × 720`: breadcrumbs, заголовок, labels, contextual-зона и actions не выходят за viewport;
- на `1079px` работает mobile shell, на `1080/1081px` — desktop sidebar;
- `documentElement.clientWidth === scrollWidth` и form-surface `clientWidth === scrollWidth` на всех шести ширинах; `overflow-x` документа остаётся `visible`, результат не маскируется;
- computed primary CTA: белый `rgb(255,255,255)` на `rgb(49,95,84)`, contrast ≈ `7.2:1` с учётом глобального `a { color: inherit }`;
- keyboard trail прошёл back link, оба input, return link, primary action и mobile navigation; поля получили focus shadow `4px`, actions — outline `3px`;
- isolated long-word fixture на `320 / 390 / 761 / 1080px` не обнаружила выходящих за viewport элементов и горизонтального overflow.

Скриншоты `1440/390/320` просмотрены вручную. Демонстрационная кнопка в макете имеет `type="button"`; submit и создание данных не выполнялись.

## Live QA production-компонента

Проверка выполнена 2026-09-16 на точном webpack dev-сервере worktree `http://localhost:3017`. Неавторизованный Playwright при открытии `/dashboard/collections/new` корректно получил redirect на `/login`; доступный Chrome-профиль с сохранённой сессией отсутствовал, а подключение локального `.env` было отклонено контролем безопасности. Auth не обходился, cookie/token не читались.

Для mutation-free визуальной проверки использовался временный route `/d07-fixture`, который собирал реальный `DashboardShell`, `DashboardPageNav` и production `CollectionCreateSection` с no-op action. Fixture не отправлялась и удалена до коммита.

- скриншоты production-компонента `1440×900`, `390×844`, `320×720` просмотрены вручную: sidebar/bottom navigation переключаются корректно, все поля и actions видимы, форма имеет одну поверхность без вложенных `Panel`;
- `documentElement.clientWidth === scrollWidth` и form-surface `clientWidth === scrollWidth` на `1440 / 390 / 320 / 761 / 780 / 821 / 900 / 1024 / 1079 / 1080 / 1081 / 1100 / 1180 / 1280px`;
- точная shell boundary: mobile shell на `1079px`, desktop sidebar на `1080/1081px`;
- оба input и обе form actions полностью находятся внутри viewport на всех 14 ширинах;
- isolated long-word fixture сначала выявила min-content overflow у неразрывного текста в `label`/description; локальный wrapper полей получил `min-w-0` и `overflow-wrap:anywhere`. После исправления `document` и form-surface имеют нулевую разницу `scrollWidth - clientWidth` на `320 / 390 / 761 / 780 / 1079 / 1080 / 1081 / 1100px`;
- пустое required-поле: `input.checkValidity() = false`, `form.checkValidity() = false`, `reportValidity() = false`, фокус перемещён на `collection-title`; после локального заполнения оба `checkValidity() = true`, URL не изменился и submit не выполнялся;
- keyboard trail: `Назад` → breadcrumbs → оба input → `Вернуться к списку` → `Создать подборку` → mobile navigation. Shared inputs/actions имеют видимый focus ring; breadcrumbs сохраняют существующий shared focus-color;
- feedback fixture показала существующие сообщения `Проверьте заполнение полей и попробуйте еще раз.` и `Коллекция создана.` без изменения feedback mapping;
- computed contrast: primary button `5.17:1`, secondary link `15.57:1`; белый текст primary не зависит от глобального `a { color: inherit }`, secondary link сохраняет корректный inherited color;
- shell sheet `Ещё`: после открытия `body overflow = hidden`, `Shift+Tab` остаётся внутри dialog; resize `320→1180` не снимает trap/lock; `Escape` закрывает dialog и возвращает `body overflow = visible`;
- чистый Playwright-прогон после ожидания hydration: console/page errors `0`;
- default agent consumer общего `CollectionCreateSection` отдельно открыт через fixture: прежние заголовок, placeholder и default panel-layout сохранены, document overflow отсутствует.

На D07 нет выбора объектов/номеров и соответствующей modal: эти действия начинаются после создания на D08 и этой задачей не менялись. Production submit, redirect после создания и server validation не проверялись, потому что разрешённой staging fixture не было.
