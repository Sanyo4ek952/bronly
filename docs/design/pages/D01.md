# D01 — Главная кабинета владельца

Маршрут: `/dashboard`

Статус: визуальный дизайн до production-реализации.

Опора: `docs/product/prd.md` §§4.1, 5.2, 5.8, 6, 8, 9–11, 15, 17; `docs/design/rollout.md`; визуальный язык `src/widgets/landing-page/landing-page.tsx`.

## Задача страницы

Главная кабинета должна за несколько секунд отвечать владельцу на три вопроса:

1. Готова ли публичная витрина и доступна ли она гостям?
2. Что сейчас требует внимания: новые заявки, заполнение витрины или подписка?
3. Куда перейти для частых действий?

Страница не становится аналитическим дашбордом или CRM. Она остаётся мобильной стартовой точкой к объектам, отдельным номерам, календарю занятости, заявкам, публичной странице, подписке и персональным приглашениям.

## Audit текущей реализации

### Данные и состояния, которые сохраняются

- количество объектов, всех и активных номеров, новых заявок;
- тариф, статус и срок подписки;
- публичная ссылка или переход к настройке slug;
- ограничение кабинета, grace/expired предупреждение;
- `ready`, `demo`, `unavailable`;
- пустое состояние без объектов;
- пустое состояние без номеров при существующем объекте;
- пятишаговый онбординг с `done`, `current`, `pending`;
- счётчик непрочитанных уведомлений в shell;
- все существующие маршруты и sign out.

### Визуальные проблемы

- три одинаково тяжёлые summary-панели конкурируют за внимание;
- внутри каждой панели находится ещё одна рамочная таблица, а затем полноширинная кнопка — `Panel → border → action`;
- быстрые действия повторяют ту же схему рамок и внутренних отступов;
- приглашения занимают отдельную тяжёлую панель при низком информационном весе;
- teal-палитра `.dashboard-theme` визуально отделена от песочного/кремового/шалфейного языка главной;
- topbar оформлен ещё одной рамочной карточкой, хотя является заголовком страницы;
- на мобильном каждая карточка растягивает путь до основных действий.

## Композиция

### Desktop, 1440 px

- shell: боковая навигация 224 px на спокойной кремовой поверхности; основная колонка без внешней рамки;
- открытый page header: eyebrow `КАБИНЕТ ВЛАДЕЛЬЦА`, приветствие, пояснение; справа брендовый badge, уведомления, выход;
- единый hero-overview на мягком шалфейном фоне:
  - статус публичной витрины и основной CTA;
  - три показателя в одной строке с разделителями, без внутренних карточек;
- двухколоночная рабочая зона:
  - слева `Продолжить работу` — четыре плоских action-row в сетке 2×2;
  - справа компактный блок подписки и вторичный переход к приглашениям;
- empty states появляются перед рабочей зоной как один акцентный блок с двумя действиями, а не как дополнительные карточки;
- launcher онбординга остаётся плавающим и открывает существующий доступный dialog.

### Mobile, 390 и 320 px

- desktop sidebar скрыта, нижняя навигация остаётся из существующего shell;
- заголовок становится компактным, actions topbar остаются в первой строке;
- hero перестраивается в один столбец;
- показатели остаются в одной строке из трёх равных ячеек и используют короткие подписи;
- action-row идут одним столбцом, вся строка — удобная touch target;
- подписка и приглашения располагаются последовательно;
- фиксированный launcher чеклиста находится выше нижней навигации;
- минимальная ширина контента отсутствует, длинные тексты и URL переносятся.

## Визуальные правила

- Manrope уже подключён глобально.
- Фон: `--reserve-color-sand-50`.
- Основные поверхности: `--reserve-color-cream-50`.
- Вторичные поверхности: `--reserve-color-sand-100`.
- Акцентные поверхности: `--reserve-color-sage-50`.
- Акцент: `--reserve-color-sage-600`, hover/контрастный текст: `--reserve-color-sage-700`.
- Текст: graphite 900/700/500.
- Рамка используется только для определения внешней поверхности или разделения строк, не для каждого уровня контента.
- У каждой смысловой группы один владелец padding.
- Hero и shell получают мягкую глубину; рабочие action-row остаются плоскими.

## Интеракции и доступность

- все links сохраняют видимый `focus-visible`;
- активный nav item отмечается цветом и `aria-current`;
- уведомления сохраняют доступное имя и badge;
- launcher онбординга сохраняет `aria-expanded`, `aria-controls`, Escape и возврат фокуса;
- warning/error состояния используют текст и иконографику, а не только цвет;
- CTA публичной страницы ведёт на реальный `publicUrl`; при его отсутствии — в настройки;
- весь action-row кликабелен, без вложенных интерактивных элементов.

## Матрица состояний

| Состояние | Представление |
| --- | --- |
| `ready`, витрина доступна | шалфейный hero, статус `Открыта для гостей`, CTA `Открыть страницу` |
| нет `publicUrl` | hero с текстом о настройке адреса, CTA `Настроить ссылку` |
| `grace` | warning notice перед hero, данные и действия остаются видимыми |
| `expired` / restricted | notice + компактный блок продления с переходом к подписке |
| `demo` | soft notice `Демонстрационный режим`; тестовые данные не маскируются под реальные |
| `unavailable` | единственный warning notice без подстановки demo data |
| нет объектов | один onboarding empty block с CTA объекта и отдельного номера |
| объект есть, номеров нет | один empty block с переходом к объектам |
| onboarding dialog | пять шагов, активный шаг раскрыт, состояния `done/current/pending` |

## Ограничение shared-изменений

D01 меняет только базовые token overrides `.dashboard-theme` и визуальную оболочку существующих `OwnerShell`/`DashboardTopbar`. Навигационные наборы, breakpoints, права, уведомления и sign out не меняются. Специфическая композиция overview остаётся в `owner-dashboard-overview`; остальные страницы не получают недизайненный новый layout.

## Демонстрационные данные макета

В `D01.html` показаны только изолированные тестовые данные: владелец `Алексей`, 2 объекта, 4 номера, 2 новые заявки, тариф `Плюс`. Они нужны для оценки и не переносятся в production data flow.
