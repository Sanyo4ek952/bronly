# D02 — Объекты и номера владельца

Маршрут: `/dashboard/properties`

Статус: реализовано в production-компонентах; live visual QA ожидает авторизованный вход пользователя.

Опора: `docs/product/prd.md` §§4.1, 5.2, 5.7, 8, 15, 17; `docs/product/decision-log.md` — «Самостоятельные номера без объекта»; `docs/design/rollout.md`; визуальный язык `src/widgets/landing-page/landing-page.tsx` и D01.

## Задача страницы

Страница должна быть единым рабочим списком инвентаря владельца, но ясно разделять два разных типа сущностей: объекты с номерами и самостоятельные номера без объекта. Владелец должен быстро найти вариант, понять его готовность к показу гостям и перейти к следующему действию.

## Audit текущей реализации

### Данные и функции, которые сохраняются

- единый набор данных владельца: объекты и самостоятельные номера;
- название, тип размещения, город, адрес и обложка;
- статус `published`, `draft`, `archived` и его текстовая метка;
- количество всех и активных номеров у объекта;
- минимальная цена, новые заявки, активные сотрудничества с агентами;
- заполненность профиля и рассчитанная активность;
- публичная ссылка, её копирование и fallback в настройки;
- включение и выключение предложений от агентов;
- поиск по названию, типу, городу и адресу;
- фильтр по статусу и сортировка по дате, названию, заявкам и активности;
- создание объекта и самостоятельного номера;
- переходы к номерам/параметрам, календарю занятости, заявкам, настройкам и публичной странице;
- success/error feedback, loading, общий empty state и empty state фильтра.

### Проблемы текущей композиции

- объекты и самостоятельные номера смешаны в одном потоке, хотя PRD фиксирует их как разные формы инвентаря;
- создание объекта/номера повторяется в header и отдельной панели «Быстрые действия»;
- пять самостоятельных stat cards создают лишний визуальный вес до рабочего списка;
- карточка использует рамочную поверхность, внутри которой ещё одна четырёхколоночная рамочная сетка, ссылка и footer;
- правая колонка состоит из трёх одинаково тяжёлых панелей; подсказка и дублированные действия конкурируют с данными;
- часть акцентов использует старые blue/teal оттенки вместо песочной, кремовой и шалфейной системы;
- мобильная кнопка поиска пытается сфокусировать desktop-поле, скрытое на mobile;
- адрес, число активных номеров и число активных сотрудничеств доступны в данных, но не помогают владельцу в карточке.

## Композиция

### Desktop, 1440 px

- открытый page header без внешней карточки: eyebrow, заголовок и описание слева, два действия создания справа;
- единая шалфейная summary-полоса с пятью показателями и разделителями, без пяти вложенных карточек;
- одна компактная toolbar-поверхность: поиск, статус и сортировка;
- основная колонка содержит две явные группы:
  - `Объекты` — карточки объектов с количеством всех/активных номеров;
  - `Самостоятельные номера` — те же рабочие данные без искусственного родительского объекта;
- каждая карточка — одна кремовая поверхность: обложка, identity, статус, адрес, плоская строка метрик, публичная ссылка, agent toggle и действия;
- справа только один блок `Готовность витрины`: средний процент и три строки breakdown. Дублированные CTA и декоративная подсказка удалены.

### Mobile, 390 и 320 px

- header и обе CTA переходят в один столбец;
- summary становится горизонтально компактной сеткой 2×2 плюс полноширинные новые заявки, без горизонтального скролла;
- мобильный поиск — реальное видимое поле; статус и сортировка открываются в существующем `BottomSheet`;
- группы сохраняют отдельные заголовки и счётчики;
- карточка становится одноколоночной: обложка, identity, метрики 2×2, ссылка, toggle, три основных действия и menu;
- длинные названия, адреса и публичные ссылки переносятся или обрезаются внутри доступной ширины;
- touch targets — не меньше 44 px, нижняя навигация shell остаётся доступной.

## Визуальные правила

- Manrope уже подключён глобально.
- Фон: `--reserve-color-sand-50`; поверхность: `--reserve-color-cream-50`; вторичный фон: `--reserve-color-sand-100`; акцентная поверхность: `--reserve-color-sage-50`.
- Акцент: `--reserve-color-sage-600`; контрастный акцент: `--reserve-color-sage-700`; основной текст: graphite 900/700/500.
- Синий декоративный trend-график и blue stat tones удаляются; состояния остаются различимы текстом, иконкой и спокойным semantic tint.
- У каждой смысловой группы один владелец padding. Внутри карточки используются разделители и gap, а не дополнительные Panel.
- Общие `Button`/`ButtonLink`, `BottomSheet`, `InlineNotice` переиспользуются без изменения defaults.

## Состояния

| Состояние | Представление |
| --- | --- |
| данные загружены | summary, toolbar, одна или две непустые группы, готовность витрины |
| только объекты | группа объектов; группа самостоятельных номеров не рисуется |
| только самостоятельные номера | группа самостоятельных номеров; группа объектов не рисуется |
| пустой инвентарь | один empty block с двумя CTA создания |
| фильтр без результатов | один filter-empty block и кнопка сброса фильтров |
| feedback success/error | существующий `InlineNotice` сразу после header |
| loading | skeleton повторяет header, summary, toolbar и карточки без ложной боковой перегрузки |
| error | один спокойный error block с действием `Повторить` |
| нет публичной ссылки | текст `Сначала заполните публичный профиль`, copy disabled, open ведёт в настройки |
| agent toggle pending | контрол disabled, визуально снижена opacity |

## Доступность и интеракции

- для search и select есть видимые или screen-reader labels;
- фильтры и сортировка управляются клавиатурой; mobile sheet сохраняет focus trap, Escape и возврат фокуса;
- menu использует доступное имя конкретного варианта; links получают общий `focus-visible` ring;
- статус, тип сущности и число новых заявок не кодируются одним цветом;
- copy сообщает `Скопировано` через доступный текст;
- agent toggle имеет доступное имя с названием сущности;
- внешний переход на публичную страницу сохраняет `target=_blank` и `rel=noreferrer`.

## Ограничение изменений

D02 меняет только страницу `/dashboard/properties`, её локальные property-inventory widgets и согласованные loading/error states. Глобальные токены, shell, другие dashboard pages, data loader, server actions и права не меняются. Новый shared-компонент не требуется.

## Демонстрационные данные макета

В `D02.html` используются только изолированные данные: два объекта и один самостоятельный номер, статусы, цены, заявки и проценты готовности. Они не переносятся в production data flow.

## Результаты визуального QA макета

Проверка выполнена 2026-09-15 через локальный HTTP-сервер и Playwright Chromium. Проверялся изолированный `D02.html`, а не закрытая production-страница.

- `1440 × 1000`: sidebar виден, bottom navigation скрыта; summary остаётся одной полосой, объекты и самостоятельные номера образуют отдельные группы, readiness занимает одну компактную боковую поверхность.
- `390 × 844`: sidebar скрыт, bottom navigation видна; CTA, summary 2×2+1, реальный mobile search и карточки переходят в один столбец.
- `320 × 720`: CTA складываются вертикально, длинные заголовки и счётчики групп переносятся, карточки и actions остаются внутри viewport.
- Full-page снимки всех трёх ширин просмотрены вручную; фиксированная bottom navigation в full-page stitching повторяется в позиции viewport, что является особенностью снимка, а не layout overflow.

| Проверка | 1440 px | 390 px | 320 px |
| --- | --- | --- | --- |
| `documentElement.clientWidth` | 1440 | 390 | 320 |
| `documentElement.scrollWidth` | 1440 | 390 | 320 |
| Горизонтальный overflow | нет | нет | нет |
| Console errors | 0 | 0 | 0 |
| Sidebar | виден | скрыт | скрыт |
| Bottom navigation | скрыта | видна | видна |

Keyboard-проверка прошла восемь последовательных `Tab` на каждом viewport; все посещённые links, inputs и buttons получили сплошной `focus-visible` outline 3 px. Фактические computed styles primary CTA: белый текст `rgb(255, 255, 255)` на шалфейном фоне `rgb(71, 118, 104)`, контраст `5.17:1`. Дополнительно: graphite 900 / sand 50 — `15.14:1`, graphite 500 / sand 50 — `4.63:1`, sage 700 / sage 50 — `6.63:1`.

Снимки находятся вне git в локальных QA-артефактах: `d02-design-1440.png`, `d02-design-390.png`, `d02-design-320.png`.

## Live QA production-компонентов

Отдельный dev-сервер ветки запущен на `localhost:3012` через webpack; production build и маршрут `/dashboard/properties` компилируются. Доступная обычная browser UI-сессия не авторизована: запрос к закрытому маршруту корректно вернул `307` и открыл `/login`. Cookies, токены и сохранённые поля не читались, auth bypass не применялся.

Поэтому visual/live проверки production-компонентов на `1440/390/320`, реальных фильтров, BottomSheet, copy/menu/navigation и agent toggle остаются непроверенными до ручного входа пользователя именно на `localhost:3012`. Изолированный HTML QA не засчитывается как live QA.
